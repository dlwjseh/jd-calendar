# 이벤트 등록 기능 설계 (Event Feature)

> JD Calendar v1의 이벤트 등록 기능을 단계별로 구체화하는 설계 문서.
> 합의된 항목만 본문에 채우고, 미정 항목은 `TBD`로 둔다.

## 1. 데이터 모델

이벤트는 SwiftData `@Model` 클래스로 정의한다. 카테고리와 같은 `ModelContainer`를
공유하며(`CATEGORY_FEATURE.md` §4), **정확히 1개의 카테고리를 필수로** 가진다
(`CATEGORY_FEATURE.md` §2). 색상은 카테고리에서 오므로 이벤트는 별도 색 필드를 두지 않는다.

### 1.1 필드

| 필드        | 타입             | 비고 |
|------------|-----------------|------|
| `id`       | `UUID`          | 생성 시 부여, 변경 불가. `@Attribute(.unique)` |
| `title`    | `String`        | 빈 문자열·공백만 금지. v1엔 길이 상한 두지 않음 |
| `startAt`  | `Date`          | 시작 시각. 종일이면 시작 날짜 00:00으로 정규화 |
| `endAt`    | `Date`          | 종료 시각. 종일이면 끝나는 날 + 1일 00:00 (iCal식 배타적) |
| `isAllDay` | `Bool`          | 종일 여부 |
| `note`     | `String`        | 옵셔널 의미를 빈 문자열로 표현 (`Category.note`와 동일 방식) |
| `createdAt`| `Date`          | 생성 시각. v1엔 정렬·기능 사용 없음 (메타데이터 용도) |
| `category` | `Category` 관계  | 비옵셔널, 정확히 1개. inverse는 `Category` 측 |

### 1.2 시간 / 멀티데이 조합
- 종일/시간지정과 단일/멀티데이는 **자유롭게 조합** 허용. 다음 4가지 모두 OK.
  - 종일 · 단일일
  - 종일 · 멀티데이
  - 시간지정 · 단일일
  - 시간지정 · 멀티데이
- 종일(`isAllDay == true`)일 때 정규화 규칙
  - `startAt` = 시작 날짜의 00:00
  - `endAt`   = 마지막 날 + 1일의 00:00 (**배타적**, iCal 관행과 동일)
  - 사용자에게는 "끝나는 날 포함"으로 보여준다 (변환은 §4·§5에서 다룸).
- 시간지정(`isAllDay == false`)일 때
  - `startAt` / `endAt`은 분 단위까지 의미 있게 저장. 초 이하는 0으로 정규화.

### 1.3 검증
- `title`이 빈 문자열 또는 공백만이면 저장 거부.
- `endAt > startAt`을 항상 보장한다 (동일 시각 이벤트는 v1엔 허용하지 않음).
- `category`는 nil 불가 — 모델 선언에서 비옵셔널로 강제.

### 1.4 관계 / 삭제 정책
- `Category` 쪽에 `@Relationship(deleteRule: .cascade, inverse: \Event.category)`
  형태의 컬렉션을 두어, 카테고리 삭제 시 그 카테고리에 속한 이벤트도 함께 삭제된다
  (`CATEGORY_FEATURE.md` §1 / §8).
- 이벤트 자체 삭제는 `ModelContext.delete(_:)`로 처리 (관계는 자동 정리).

### 1.5 v1엔 두지 않는 것 (필요 시 추후 추가)
- 알림(reminder), 반복(recurrence), 참석자(attendees)
- 위치(location), URL, 첨부파일
- 색상 오버라이드 (카테고리 색을 그대로 따른다)
- `updatedAt` 등 추가 메타데이터

## 2. 저장소 (Persistence)

`CATEGORY_FEATURE.md` §4의 결정을 그대로 따른다.

- 백엔드: **SwiftData**
- `ModelContainer`는 카테고리와 공유: `.modelContainer(for: [Category.self, Event.self])`
  를 `JDCalendarApp.swift`의 `WindowGroup`에 부착.
- 저장 위치: SwiftData 기본값
  (`~/Library/Application Support/com.jd.JDCalendar/default.store`).
- 마이그레이션: v1엔 불필요 (스키마 v2로 넘어갈 때 정함).
- 리스크: macOS 14 초기 SwiftData 버그 — `CATEGORY_FEATURE.md` §4.4 참조.

## 3. 생성 UI

### 3.1 진입 경로
새 이벤트 다이얼로그는 다음 두 가지 방법으로 띄운다.

- **셀 더블클릭** — 해당 날짜로 시작·종료가 자동 채워진 채 열린다.
- **셀 우클릭 → 컨텍스트 메뉴 `이벤트 추가`** — 더블클릭과 동일한 다이얼로그를 띄운다.
  (메뉴의 그 외 항목은 §5에서 정함.)

헤더 `+` 버튼이나 `Cmd+N` 단축키는 v1에서 두지 않는다.

### 3.2 다이얼로그 형태
- 카테고리 다이얼로그(`CATEGORY_FEATURE.md §5.5`)와 동일한 패턴 — **화면 중앙 모달 시트**.
- 윈도우 타이틀: 신규 시 `새 이벤트`, 편집 시 `이벤트 편집`. 모드 구분은 타이틀로만.
- 폼 내부 필드 라벨은 두지 않고, 플레이스홀더로만 의미를 표시한다 (카테고리와 동일).

### 3.3 폼 구성
폼은 위에서 아래로 다음 순서로 배치한다.

1. **카테고리 줄** — 최상단. 드롭다운(`Picker`). 항목마다 `색상 점 + 이름`을 함께 표시.
2. **제목 줄** — 좌측에 카테고리 색상 점(1번에서 선택된 색을 반영, **표시 전용**) + 한 줄
   텍스트 필드. 플레이스홀더 `제목`. 1번에서 카테고리 변경 시 색 점이 즉시 갱신된다.
3. **종일 토글** — 토글 한 개. 켜져 있으면 4·5의 시각 인풋이 숨겨진다.
4. **시작 줄** — `날짜 / 시각` 두 인풋이 같은 줄에. 종일이면 `시각` 숨김.
5. **종료 줄** — 시작과 같은 형태.
6. **메모 영역** — 처음에는 `메모 추가` 버튼 한 개만 보인다. 버튼을 누르면 그 자리에
   멀티라인 `TextEditor`로 교체된다. 편집 모드에서 기존 메모가 비어있지 않으면 시작부터
   `TextEditor`가 보인다. 플레이스홀더 `메모 (옵션)`.
7. **버튼 줄** — 우측 정렬 `취소` / `저장` (카테고리와 동일).

### 3.4 초기값
- **종일 토글**: **on** (종일 모드로 시작).
- **시작·종료 날짜**: 진입한 셀의 날짜 — 시작·종료 같은 날(단일일).
- **시각** (시간지정으로 토글했을 때의 기본값): 시작 `09:00` / 종료 `10:00` (1시간 기본).
- **카테고리**: 마지막에 사용한 카테고리. 처음 사용 시 시드 `기본`.
  - 마지막 사용 카테고리 id(UUID 문자열)를 `@AppStorage` 키 하나에 저장한다.
- **제목·메모**: 빈 상태.

### 3.5 키보드 / 동작
- `Esc` = 취소, `Cmd+Enter` 또는 `Enter`(메모 포커스가 아닐 때) = 저장. (카테고리와 동일)
- 시작 변경 시 종료가 자동 따라감 — 기존 길이(`endAt - startAt`)를 유지한다 (EventKit 표준 패턴).
- 종일 ↔ 시간지정 토글 시 동작:
  - 종일 → 시간지정: 같은 날짜 위에 `09:00` / `10:00`을 자동 채움.
  - 시간지정 → 종일: 시각은 버리고 날짜만 유지.
- `저장`은 제목이 비어있지 않고 `endAt > startAt`(정규화 후 비교)을 만족할 때만 활성.

## 4. 캘린더 셀 내 표시

`CATEGORY_FEATURE.md` §6·§7이 "EVENT_FEATURE 작업 시 같이 정함"으로 미뤄놨던 부분을 여기서 함께 정한다.

### 4.1 이벤트 항목 모양
종일 / 시간지정에 따라 셀 안에서 모양이 다르다.

**종일 이벤트** — 색 배경 박스 + 제목 한 줄
- 셀 너비를 거의 채우는 가로 박스. 모서리는 살짝 둥글게.
- 배경색 = 카테고리 색.
- 텍스트 색은 카테고리 색의 명도에 따라 **흰색/검정 자동 결정** (대비 우선).
  팔레트의 `#BFBFBF`(Light Gray) 같은 밝은 색은 검정 텍스트.
- 시각 prefix 없음 (제목만).

**시간지정 이벤트** — 얇은 색 바 + 시각 prefix + 제목
- 좌측에 얇은 세로 색 바(카테고리 색) + 그 옆에 `HH:mm 제목` 형태 한 줄 텍스트.
- 텍스트 색은 페이지 기본 텍스트 색 (배경이 페이지이므로 대비 이슈 없음).
- 예: `09:00 회의`.

### 4.2 한 셀 안 최대 표시 개수
- 셀당 최대 **3개**까지 항목을 보여주고, 그 이상은 마지막 줄에 `+M more`로 축약한다.
  (예: 5개 있으면 3개 + `+2 more`.)
- N=3은 v1 고정. 셀 높이가 가변이 되면 추후 조정.
- 카운트는 **셀이 차지하는 모든 트랙 합계** 기준 — 멀티데이 막대(§4.3)도 한 셀에서 트랙
  하나씩 차지하므로 이 합산에 포함된다. 예: 멀티데이 2개가 지나가는 셀에 단일일 이벤트 2개가
  있으면 트랙 4 → 위에서 3개 표시, 마지막 줄은 `+1 more`.
- `+M more` 클릭 시 동작은 §5.6 참조 (그 셀이 세로로 확장되어 그 날의 모든 이벤트를 표시).

### 4.3 멀티데이 이벤트
**가로로 이어지는 한 줄 색 박스**로 그린다 — 종일/시간지정 둘 다 같은 모양.

- §4.1의 색 배경 박스가 여러 셀을 가로질러 이어진다.
- 종일/시간지정 모두 시각 prefix는 표시하지 않고 **제목만**. 텍스트 색은 §4.1과 같은 자동
  대비(흰/검정).
- 제목은 시작 셀에만 표시. 막대가 길어 텍스트가 잘리면 ellipsis(`…`)로 축약.
- 주(week) 경계를 넘는 이벤트는 그 다음 주의 첫 셀에서 막대가 다시 시작되며, 제목은 거기서도
  한 번 더 표시한다.
- 양 끝 여백 — segment의 시작 셀 좌측과 끝 셀 우측은 단일일 chip과 같은 셀 내부 padding
  (좌우 6pt)을 따른다. 같은 segment 안 셀들 사이는 padding을 두지 않아 가로 연속성을 유지한다.
- 구현 토대: 주 단위 overlay layer로 그린다. `CalendarGrid.swift`의 셀(VStack of HStacks)
  구조 위에 주(HStack) 단위 overlay + `GeometryReader`로 셀 가로폭을 받아 막대를 정확히
  배치한다. 셀 안에서는 막대가 차지할 트랙 수만큼 invisible spacer를 깔아 단일일 chip이
  자연스럽게 그 아래로 정렬되도록 한다.

### 4.4 카테고리 필터 연동
- `Category.isVisible == false`인 카테고리의 이벤트는 셀 표시에서 **제외**된다.
- 사이드바에서 색상 점 체크를 토글하면 즉시 반영된다.
- 숨겨진 이벤트는 §4.2의 N 카운트(`+M more`)에도 포함되지 않는다 (멀티데이 막대도 마찬가지).
- 셀의 클릭·우클릭·편집 진입에서도 숨겨진 이벤트는 노출되지 않는다.

### 4.5 정렬 순서 (트랙 stack 순서)
한 셀 안에 여러 이벤트가 있을 때 위에서부터 다음 순서로 트랙(stack)을 쌓는다.

1. **멀티데이 막대가 항상 위쪽 트랙** — 가로 연결이 끊어 보이지 않도록(시각 우선).
   같은 주 내 여러 멀티데이가 겹치면 시작이 빠른 것부터 위 트랙.
2. 그 다음 **단일일 종일 이벤트**, `startAt` 오름차순.
3. 그 다음 **단일일 시간지정 이벤트**, `startAt` 오름차순.
4. 동일 시각이면 `createdAt` 오름차순으로 타이 해소.

## 5. 상세 / 편집 / 삭제

### 5.1 셀 항목 인터랙션
- **단일 클릭** — 항목이 **선택 상태**가 되며 시각적 강조가 표시된다 (외곽 링 등 — 구체
  스타일은 v1 구현 시 결정).
- **더블 클릭** — 편집 시트(§5.2)로 진입.
- **우클릭** — 컨텍스트 메뉴(§5.5).
- **`Delete` / `Backspace` 키** — 선택된 항목을 삭제(§5.4 확인 다이얼로그를 거침).
- **선택 해제** — 다른 영역 클릭 또는 `Esc`.
- 한 번에 **한 항목만** 선택. 다중 선택은 v1엔 없음.

### 5.2 편집 다이얼로그
- §3의 생성 시트를 **그대로 재사용**한다. 윈도우 타이틀만 `이벤트 편집`으로 변경.
- 폼 구성·키보드 동작은 §3 그대로. 초기값은 편집 모드에선 기존 이벤트 값으로 채움.
- **편집 모드일 때만** 좌측 하단에 `삭제` 버튼을 노출한다 (macOS HIG의 destructive
  좌측 정렬). 신규 모드에는 `삭제` 버튼 없음.
  - `삭제` 클릭 → §5.4 확인 다이얼로그 → 확인 시 이벤트 삭제 후 시트 닫힘.
- `저장` 시 카테고리·제목·시간 등이 변경되었다면 변경 사항이 반영된다.

### 5.3 삭제 진입점 (요약)
모든 진입점은 §5.4 확인 다이얼로그를 거친 뒤 실제 삭제된다.

- 편집 시트 좌측 하단 `삭제` 버튼 (§5.2).
- 셀 항목 우클릭 → `삭제` (§5.5).
- 선택 상태에서 `Delete` / `Backspace` 키 (§5.1).

### 5.4 삭제 확인 다이얼로그
- **제목**: `"<제목>"을 삭제할까요?` (예: `"회의"를 삭제할까요?`)
- **본문**: 없음.
- **버튼**: `취소` / `삭제` (`.destructive`, 빨간색 강조).
- **기본 버튼은 `취소`** — Enter 실수 방지 (카테고리 §8.3과 동일).
- `Esc` = `취소` (시스템 기본).

### 5.5 항목 우클릭 컨텍스트 메뉴
- 셀 안 이벤트 항목 위에서 우클릭 시 다음 두 항목.
  - `편집` → §5.2 편집 시트 진입.
  - `삭제` → §5.4 확인 다이얼로그.
- 빈 영역(셀 본체) 우클릭은 §3.1의 `이벤트 추가` 메뉴 그대로.

### 5.6 `+M more` 동작 — 셀 세로 확장
§4.2의 `+M more`을 클릭하면 그 셀이 **세로로 확장**되어 그 날의 모든 이벤트가 보인다.

- 확장된 셀은 월 그리드 레이아웃을 깨지 않도록 다른 셀 위에 띄운다 (overlay/z-order
  처리 — 구체 전략은 v1 구현 시 결정).
- 확장된 영역의 항목들은 §4.1과 동일한 모양으로 그리고, 정렬은 §4.5를 따른다.
- 항목 인터랙션(단일/더블/우클릭/Delete)은 §5.1과 동일.
- **확장 해제 트리거**:
  - 다른 셀(또는 그 외 영역) 클릭 시 자동 닫힘.
  - `Esc` 키.
- **동시 확장은 한 번에 한 셀만**. 다른 셀의 `+M more`을 누르면 직전에 확장된 셀은
  자동으로 접힌다.

## 6. 상호작용 (추가)

§3·§5에서 정한 핵심 인터랙션 외에 v1에 포함되는 추가 인터랙션은 다음 두 가지다.

### 6.1 드래그로 이벤트 날짜 이동
- 셀 위 이벤트 항목을 잡고 다른 셀로 드래그하면 날짜가 변경된다.
- **시간은 유지된다** — 종일은 종일 그대로, 시간지정은 기존 시각 유지.
- 멀티데이 이벤트는 **시작·종료가 함께 평행 이동**한다 (길이 보존).
  예: `5/1 ~ 5/3` 종일을 `5/4`로 드롭 → `5/4 ~ 5/6`.
- 멀티데이 막대는 어느 위치를 잡아도 드래그가 시작된다.
- 드롭 가능한 셀에 시각적 강조 (외곽 링 등 — 구체 스타일은 v1 구현 시 결정).
- 유효한 셀이 아닌 곳 또는 원래 위치에 드롭하면 변경 없이 무시된다.
- **드롭 즉시 저장** — 확인 다이얼로그 없음.
- 카테고리 필터로 숨겨진 항목은 화면에 없으므로 드래그 대상이 아니다.

### 6.2 트랙패드 / 휠 가로 스와이프로 월 이동
- 가로 스와이프 / 가로 스크롤로 이전·다음 달 이동 (헤더의 `‹ ›` 버튼과 동일 동작).
  - 좌→우 스와이프 = **이전 달**.
  - 우→좌 스와이프 = **다음 달**.
- 한 번의 제스처 = 한 달 이동. 임계 누적값을 넘었을 때 한 번만 발화한다.
- 전환 애니메이션은 헤더 버튼 클릭과 동일.
- 세로 스크롤은 별도 동작 없음.

### 6.3 v1엔 두지 않는 것
- 드래그로 이벤트 **길이(기간) 조절**.
- 셀 사이 **드래그로 새 이벤트** 만들기.
- 키보드 네비게이션 (방향키로 셀 이동 등).
- 오늘로 점프 **단축키** (`Cmd+T` 등). 헤더의 `Today` 버튼만 사용.
