# 카테고리 관리 기능 설계 (Category Feature)

> JD Calendar에서 이벤트를 분류할 카테고리(Category)의 관리 기능을
> 단계별로 구체화하는 설계 문서.
> 합의된 항목만 본문에 채우고, 미정 항목은 `TBD`로 둔다.
>
> 관련 문서: [EVENT_FEATURE.md](./EVENT_FEATURE.md)

## 1. 데이터 모델
카테고리는 SwiftData `@Model` 클래스로 정의한다 (4번 참조). 가지는 속성:

| 필드        | 타입      | 비고 |
|------------|----------|------|
| `id`       | `UUID`   | 생성 시 부여, 변경 불가. SwiftData `@Attribute(.unique)` |
| `name`     | `String` | 1~20자, 빈 문자열 금지 |
| `color`    | `String` | Hex 문자열 (`#RRGGBB`). 5.7 팔레트 또는 자유 색 |
| `note`     | `String` | 옵셔널, 멀티라인, 길이 제한 없음 (빈 문자열 허용) |
| `createdAt`| `Date`   | 생성 시각. v1은 정렬 기준으로 사용 |
| `isVisible`| `Bool`   | 사이드바 필터 체크 상태. 기본값 `true`. 다음 실행에도 유지 |

- 정렬: v1에서는 `createdAt` 오름차순 고정. 사용자 reorder UI 없음.
- `updatedAt` 등 추가 메타데이터는 v1엔 두지 않는다 (필요해질 때 추가).
- 이벤트 모델과의 관계는 SwiftData `@Relationship(deleteRule: .cascade)`로 표현되며,
  카테고리 삭제 시 그 안의 이벤트가 함께 삭제되도록 한다 (8번 정책과 정합).

## 2. 이벤트와의 관계
- 한 이벤트는 **정확히 1개**의 카테고리를 가진다 (카테고리 필수, 미분류 없음).
- 따라서 앱에는 항상 최소 1개 이상의 카테고리가 존재해야 한다 → 3번 섹션의 시드 정책과
  8번 섹션의 삭제 정책에서 이 불변식을 보장한다.

## 3. 기본 카테고리 (시드)
- 첫 실행 시 **단 1개의 기본 카테고리**가 자동으로 생성된다.
- 이름·색상은 앱이 정한 고정값으로 시작하며, 사용자가 나중에 이름·색상을 자유롭게
  변경할 수 있다.
- 초기 이름: `기본`
- 초기 색상: 5.7 팔레트의 #10 **Light Gray `#BFBFBF`** — 무채에 가까워 "기본 분류"
  어감과 매칭되고, 사용자가 새 카테고리를 만들 때 자동 선택되는 색이 다른 hue로
  자연스럽게 잡힌다.

## 4. 저장소 (Persistence)

### 4.1 백엔드
- **SwiftData**를 사용한다 (macOS 14+ 가용).
- 카테고리와 이벤트는 **같은 `ModelContainer`** 를 공유한다.
  `JDCalendarApp.swift`의 `WindowGroup`에 `.modelContainer(for: [Category.self, Event.self])`
  를 붙이는 형태가 기준 (이벤트 모델은 `EVENT_FEATURE.md` 작업 시 추가).
- 저장 위치는 SwiftData 기본값을 따른다:
  `~/Library/Application Support/com.jd.JDCalendar/default.store`.

### 4.2 시드 정책 (3번 섹션과 연결)
- 앱 실행 시 `ModelContext`에서 카테고리를 조회한 결과가 **비어 있으면** 3번 섹션의
  기본 카테고리(`기본` / `#BFBFBF`)를 한 건 삽입한다 (idempotent).
- 별도의 `firstLaunch` 플래그는 두지 않는다. 비어 있다는 사실 자체가 시드 트리거.

### 4.3 v1 결정에 따라오는 약속
- **이벤트 저장소도 SwiftData**로 간다는 결정이 함께 잠긴다.
  `EVENT_FEATURE.md` 진행 시 이 전제를 따른다.
- 마이그레이션 정책(스키마 v2로 갈 때): TBD — v1엔 불필요.

### 4.4 알아둘 리스크
- macOS 14 초기의 SwiftData는 일부 버그(저장 누락·관계 갱신 지연)가 보고된 적 있다.
  배포 환경의 macOS 버전을 미리 확인하고, 문제가 보이면 14.x 최신 마이너로 올리는 걸
  우선 고려한다.

## 5. 관리 UI

### 5.1 합의된 사항
- 캘린더 본체 옆에 **사이드바**가 있고, 거기에 카테고리 목록(색상 점 + 이름)이 보인다.
- 사이드바는 **접었다 폈다** 할 수 있다.
- 사이드바를 토글하는 **아이콘 버튼**이 상단에 있다.
- 사이드바는 7번의 필터링 UI를 겸한다.

### 5.2 사이드바 기본 사양
- **위치**: 캘린더 본체의 **좌측**에 배치.
- **너비**: 고정값 (구체값 TBD, 우선 220pt 기준).
- **첫 실행 시 상태**: 펼침.
- **상태 영속**: 펼침/접힘 상태를 `@AppStorage`로 기억하여 다음 실행 시 복원.
- **토글 애니메이션**: 너비를 부드럽게 슬라이드 (`easeInOut`, 0.2~0.25초 정도).
- **토글 버튼 아이콘**: SF Symbol `sidebar.leading`.
- **토글 버튼 위치**: 카드 안쪽 맨 위에 얇은 **상단 띠**를 두고 그 좌측에 배치 (A2 안).
  사이드바와 캘린더 본체는 그 띠 **아래**에서 좌·우로 나뉜다. 토글의 화면 위치는
  사이드바 펼침/접힘과 무관하게 카드 좌상단에 고정된다.

### 5.3 카테고리 행 인터랙션
- 각 행은 **`색상 점`을 체크박스 형태**로 두고, 체크 / 체크해제로 필터를 토글한다.
  (단, 이벤트 노출/비노출 적용은 이벤트 기능 도입 시점에 함께 구현 — 7번 참조)
- 행을 **우클릭하면 컨텍스트 메뉴**가 뜨고, `편집` / `삭제`를 고를 수 있다.
- `편집`을 누르면 화면 **중앙에 편집 다이얼로그**가 뜬다 (모달 시트, 이름·색상·노트 수정).
- `삭제`는 8번 섹션의 정책을 따른다 (마지막 1개면 메뉴 비활성화, 그 외엔 확인 다이얼로그).

### 5.4 사이드바 상단 영역 / 추가 UI
- 사이드바 상단에 한 줄을 두고, **좌측엔 "카테고리" 라벨**, **우측엔 `+` 버튼**을 배치한다.
- `+` 버튼을 누르면 새 카테고리 생성 다이얼로그(편집과 동일한 폼)가 화면 중앙에 뜬다.
- 별도의 삭제 버튼은 두지 않는다 — 삭제는 5.3의 우클릭 메뉴에서만.

### 5.5 편집 / 생성 다이얼로그
화면 중앙에 모달(시트)로 뜬다. 윈도우 타이틀은 신규 시 **"새 카테고리"**, 편집 시
**"카테고리 편집"** 으로 모드를 구분한다. 폼 내부 라벨은 두지 않고 플레이스홀더로만
필드 의미를 표시한다.

#### 폼 구성 (위에서 아래로)
1. **이름 줄** — 한 줄 텍스트 필드. 좌측에 **색상 점**이 붙어 사이드바 행과 동일한
   모습으로 현재 선택 색을 미리 보여준다 (점은 클릭 비활성, 표시 전용). 플레이스홀더는
   `이름`. 입력은 1~20자, 빈 문자열 금지.
2. **색상 영역** — 5.7 팔레트 10색 스와치 + 마지막에 **`⊕` 사용자 지정 타일**. `⊕`을
   누르면 시스템 `ColorPicker`(`NSColorPanel`)가 떠 자유 색을 고를 수 있다. 선택된
   색은 스와치(또는 타일)에 외곽 링/체크로 강조된다. 자유 색을 골랐는데 그 hex가
   팔레트 색과 일치하면 해당 스와치가 선택 표시된다.
3. **노트 영역** — 멀티라인 텍스트 필드, 옵셔널. 플레이스홀더는 `노트 (옵션)`.
   `TextEditor`는 기본 플레이스홀더가 없으므로 오버레이로 직접 그린다 (구현 노트).
4. **버튼 줄** — 우측 정렬로 `취소` / `저장`.

#### 신규 생성 시 색상 초기값
- 5.7 팔레트 10색 중 **다른 카테고리에서 사용되지 않은 색**을 자동 선택.
- 자유 색은 비교 대상에서 제외 (팔레트만 walk).
- 팔레트가 모두 사용 중이면 #1 Brick으로 폴백.

#### 추가 디테일
- `이름` 입력의 길이 초과·빈 문자열 입력 시 `저장` 버튼 비활성.
- 키보드 단축키: `Esc` = 취소, `Cmd+Enter` 또는 `Enter` (포커스가 노트가 아닐 때) = 저장. 세부 사항: TBD

### 5.6 구현 토대
- `NavigationSplitView`를 쓰지 않고, 커스텀 `HStack` + 사이드바 너비 애니메이션으로 구현.
  카드 디자인과 자연스럽게 맞물리고 토글 위치(A2)도 자유롭게 둘 수 있기 때문.

### 5.7 색상 팔레트
프로토타입의 톤(웜 크림 배경 `#fdfcfa`, 강조색 `#e0524a` / `#3a7bd5`)과 어울리도록
한 단계 톤다운한 10색을 기본 팔레트로 사용한다. 5.5의 `⊕` 사용자 지정 타일을 통해
자유 색을 추가로 고를 수도 있다.

| #  | 이름        | Hex       |
|----|------------|-----------|
| 1  | Brick      | `#C8483D` |
| 2  | Coral      | `#D67857` |
| 3  | Mustard    | `#BFA13A` |
| 4  | Olive      | `#8C9B55` |
| 5  | Teal       | `#3F8C85` |
| 6  | Slate      | `#4A7DBE` |
| 7  | Indigo     | `#5C5FA8` |
| 8  | Rose       | `#C46881` |
| 9  | Stone      | `#8A7E73` |

다이얼로그에서 색 자체로 보이므로 별도 표시는 필요 없다.

## 6. 캘린더 화면에서의 표시
- 이 항목은 **이벤트 기능을 도입하는 시점**에 함께 정한다.
  ([EVENT_FEATURE.md](./EVENT_FEATURE.md) 작업과 묶어 결정)

## 7. 필터링
- 카테고리별 보기/숨기기를 **지원한다**.
- 필터 UI는 5번의 사이드바 안에서 같이 제공된다 — 사용자가 사이드바 행의
  색상 점(체크박스 형태, 5.3 참조)을 토글하면 해당 카테고리의 이벤트가 캘린더에서
  숨겨진다.
- 실제 이벤트 노출/비노출 적용은 **이벤트 기능 도입 시점**에 함께 구현한다 (6번과 동일).

## 8. 삭제 시 동작

### 8.1 정책
- **마지막 1개 남은 카테고리는 삭제할 수 없다** (앱은 항상 카테고리가 최소 1개 존재해야
  하므로 — 2번 섹션 참조). 우클릭 메뉴의 `삭제` 항목을 비활성화한다.
- 그 외의 경우, 카테고리를 삭제하면 **그 카테고리에 속한 이벤트도 모두 함께 삭제**된다
  (1번의 `@Relationship(deleteRule: .cascade)`).
- 데이터 손실이 있으므로 삭제 전에 확인 다이얼로그를 띄운다.

### 8.2 확인 다이얼로그
이벤트 개수에 따라 본문이 달라진다.

**이벤트가 1개 이상일 때**
- 제목: `"<이름>"을 삭제할까요?` (예: `"업무"를 삭제할까요?`)
- 본문: `이 카테고리의 이벤트 N개도 함께 삭제됩니다. 이 동작은 되돌릴 수 없습니다.`
- 버튼: `취소` / `삭제`

**이벤트가 0개일 때**
- 제목: `"<이름>"을 삭제할까요?`
- 본문: `이 동작은 되돌릴 수 없습니다.`
- 버튼: `취소` / `삭제`

### 8.3 버튼 동작
- `삭제` 버튼은 macOS 표준 `.destructive` 역할로 빨간색 강조.
- **기본 버튼은 `취소`** — 사용자가 엔터를 눌러도 실수로 삭제되지 않도록 안전 우선.
- `Esc` = `취소` (시스템 기본).
